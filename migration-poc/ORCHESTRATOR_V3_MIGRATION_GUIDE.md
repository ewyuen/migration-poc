# OrchestratorV3 Migration Guide

## Overview

**OrchestratorV3** is a LangGraph-based replacement for OrchestratorV2 that maintains backward compatibility while adding observability via OpenTelemetry and Langfuse.

**Key improvements:**
- Explicit workflow topology (StateGraph)
- Full tracing via OpenTelemetry
- Langfuse integration for trace visualization
- Same API as V2 (drop-in replacement)
- All existing agents unchanged

## Quick Start

### Installation

OrchestratorV3 requires additional dependencies. They are already in `requirements.txt`:

```bash
pip install -r migration-poc/requirements.txt
```

**New dependencies added:**
- `langgraph>=0.1.0` — Graph orchestration framework
- `opentelemetry-api>=1.20.0` — Tracing API
- `opentelemetry-sdk>=1.20.0` — Tracing SDK
- `opentelemetry-exporter-otlp>=0.41b0` — OTLP gRPC exporter
- `langfuse>=2.0.0` — Langfuse SDK

### Basic Usage

Replace OrchestratorV2 with OrchestratorV3 (same interface):

```python
from agents.orchestrator_v3 import OrchestratorV3
from input_handler import MigrationRequest

# Create orchestrator
orchestrator = OrchestratorV3()

# Create request
request = MigrationRequest(
    component_name="MyComponent",
    request_id="req-123",
    filters={}
)

# Run migration (identical to V2)
results = orchestrator.orchestrate_migration(request)
```

### Return Value

Same as OrchestratorV2:

```python
{
    "status": "success" | "failed",
    "run_id": "component-name-mmddyy-HHMMSS-sss",
    "stage": "verify" | "validate_failed" | ...,
    "error": None | "Error message",
    "artifacts": {
        "staging": {...},
        "exploration": {...},
        "modernization": {...},
        "bdd": "...",
        "test_code": "...",
        "verification": {...}
    }
}
```

## Configuration

### Workflow Configuration (No Change)

Use the existing `migration_config.yaml` — no changes needed.

### OpenTelemetry Configuration (Optional)

#### OTLP Exporter Endpoint

By default, OTel exports to `localhost:4317` (gRPC). Override with:

```bash
export OTEL_EXPORTER_OTLP_ENDPOINT="my-otel-collector:4317"
```

#### Langfuse Configuration

To enable trace ingestion to Langfuse SaaS:

```bash
export LANGFUSE_PUBLIC_KEY="pk-lf-..."
export LANGFUSE_SECRET_KEY="sk-lf-..."
export LANGFUSE_ENDPOINT="https://cloud.langfuse.com"  # Optional, defaults to cloud
```

If not configured, Langfuse processor will gracefully skip export.

## Architecture

### State Graph

OrchestratorV3 executes as a LangGraph StateGraph:

```
START
  ↓
[validate]
  ↓
  ├─ (error) → [verify] → END
  │
[stage]
  ├─ (error) → [verify] → END
  │
[explore]
  ├─ (error) → [verify] → END
  │
[modernize]
  ├─ (error) → [verify] → END
  │
[bdd_and_test]
  │
[verify]
  ↓
END
```

**Key property:** Every workflow continues to verification, even on failures. Verification reports the final status.

### State Schema (MigrationState)

All data flows through a TypedDict:

```python
class MigrationState(TypedDict):
    request: MigrationRequest                    # Input
    run_id: Optional[str]                        # Generated by stage
    stage: str                                   # Current stage name
    error: Optional[str]                         # Error if any
    staging_results: Optional[Dict]              # Staging output
    exploration_results: Optional[Dict]          # Exploration output
    modernized_code: Optional[Dict[str, str]]    # File → code
    bdd_tests: Optional[str]                     # Gherkin
    test_code: Optional[str]                     # C# test code
    verification_results: Optional[Dict]         # Test results
```

### OpenTelemetry Spans

Each workflow stage produces a span:

```
orchestrate_migration (root)
  ├─ node_validate
  ├─ node_stage
  ├─ node_explore
  ├─ node_modernize
  ├─ node_bdd_and_test
  └─ node_verify
```

**Span attributes:**
- `stage_name`: Name of the stage
- `status`: "success" | "failed" | "error" | "skipped"
- `run_id`: Component run identifier (if available)
- `request_id`: Request identifier
- `component_name`: Component being migrated

**Root span attributes:**
- `request_id`: From MigrationRequest
- `component_name`: From MigrationRequest

### Langfuse Integration

Langfuse subscribes to all OTel spans via LangfuseSpanProcessor. To view traces:

1. **Ensure Langfuse credentials are set** (see Configuration above)
2. **Run orchestration**
3. **Check Langfuse dashboard** → Traces section
4. Look for trace with your component_name and request_id

**Trace details include:**
- Full node execution waterfall
- Stage durations
- Error messages and stack traces
- State transitions
- All attributes

## Migration from OrchestratorV2 → V3

### No Code Changes Required!

OrchestratorV3 has the same public interface:

```python
# Old (V2)
from agents.orchestrator_v2 import OrchestratorV2
orch = OrchestratorV2()
results = orch.orchestrate_migration(request)

# New (V3) — same!
from agents.orchestrator_v3 import OrchestratorV3
orch = OrchestratorV3()
results = orch.orchestrate_migration(request)
```

Just change the import and you're done.

### Audit Trail

Both versions write to `migration-poc/audit/orchestrator.jsonl`. OrchestratorV3 writes the same format, so audit logs are compatible.

### No Agent Changes

All agents (StagingAgent, explorer, modernizer, etc.) remain unchanged. OrchestratorV3 simply calls them within LangGraph nodes.

## Observability

### Local Debugging

If running locally without Langfuse:

1. **Enable OTel console exporter** (optional setup in code)
2. **Check audit trail**: `migration-poc/audit/orchestrator.jsonl`
3. **Review stdout logs**: Each node prints its progress

### Production Observability

With Langfuse configured:

1. **Traces arrive in real-time** to Langfuse SaaS
2. **Dashboard shows:**
   - Full execution waterfall
   - Latencies per stage
   - Error detection
   - State changes
3. **Export/alert** on trace failures

## Troubleshooting

### "OTel Exporter Failed"

If you see: `⚠️ OpenTelemetry setup failed: ...`

**It's OK!** Tracing is optional. Orchestration continues.

**To fix:**
- Check `OTEL_EXPORTER_OTLP_ENDPOINT` is reachable
- Or unset it to skip local collection

### Langfuse Traces Not Appearing

**Check:**
1. `LANGFUSE_PUBLIC_KEY` and `LANGFUSE_SECRET_KEY` are set
2. No network errors in stderr
3. Orchestration completed successfully (check audit log)

**Langfuse export failures do NOT block orchestration.** Traces will be dropped but migration continues.

### Comparing V2 vs V3 Results

The return dict is the same, but V3 adds observability:

```python
# Both return identical structure
results = orch.orchestrate_migration(request)
assert results["status"] in ["success", "failed"]
assert "artifacts" in results
```

## Performance

- **No overhead** from LangGraph itself (minimal framework cost)
- **OTel span creation**: ~1ms per node
- **Langfuse export**: Async (non-blocking)

**Total impact:** <100ms for a full 6-stage workflow.

## Rollback

If you need to rollback to V2:

```python
# Just import V2 instead
from agents.orchestrator_v2 import OrchestratorV2
orch = OrchestratorV2()
results = orch.orchestrate_migration(request)
```

No data migration needed. Audit logs are compatible.
